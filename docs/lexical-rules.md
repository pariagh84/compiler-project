# قواعد لغوی

Lexer یک ماشین حالت دستی است: حالت آغاز بر اساس کاراکتر ورودی به مسیر شناسه، عدد، نقل‌قول، توضیح یا علامت می‌رود. `peek` بدون مصرف نگاه می‌کند و `advance` ورودی را جلو می‌برد. نیازی به کتابخانهٔ Regex در بخش اصلی برنامه نیست؛ عبارت‌های زیر مشخصات رسمی توکن‌ها هستند.

## الگوها

در این جدول `\\` در عبارت منظم یک بک‌اسلش واقعی را نشان می‌دهد. کاراکترهای ثابت رشته و نویسه ASCII هستند؛ newline خام داخل آن‌ها مجاز نیست.

| دسته | عبارت منظم یا مجموعهٔ دقیق |
|---|---|
| شناسه | `[A-Za-z_][A-Za-z0-9_]*` با طول حداکثر ۲۵۶ |
| عدد صحیح | `[0-9]+` |
| بولین | `true\|false` به‌معنی انتخاب میان دو واژه |
| کلمهٔ کلیدی | `array boolean char else for function if integer print return string void while` |
| رشته | `"([^"\\\r\n\x00\x80-\xFF]\|\\[^\r\n\x00\x80-\xFF])*"`؛ توضیح مجموعهٔ بدنه در ادامه |
| نویسه | `'([^'\\\r\n\x00\x80-\xFF]\|\\[^\r\n\x00\x80-\xFF])'`؛ توضیح مجموعهٔ بدنه در ادامه |
| عملگر دوتایی | `++ -- <= >= == != && \|\|` |
| عملگر تکی | `+ - * / % ^ ! < > =` |
| جداکننده | `( ) { } [ ] , : ;` |
| توضیح خطی | `//[^\r\n]*` |
| توضیح بلوکی | `/\*([^*]\|\*+[^*/])*\*+/` |
| فاصلهٔ سفید | `[ \t\r\n]+` |

برای رفع تفاوت موتورهای Regex و escape در جدول Markdown، تعریف دقیق بدنهٔ نقل‌قول چنین است: `ordinary` هر بایت ASCII غیر از NUL، CR، LF، بک‌اسلش و کوتیشن همان توکن است؛ `escape` یک بک‌اسلش و سپس یک بایت ASCII غیر از NUL، CR و LF است. رشته برابر کوتیشن دوتایی + صفر یا چند `(ordinary | escape)` + کوتیشن دوتایی است. نویسه دقیقاً یک واحد `(ordinary | escape)` دارد. این تعریف، تب خام و دیگر بایت‌های کنترلی ASCII به‌جز موارد استثناشده را نیز می‌پذیرد.

رشته پس از احتساب هر escape به‌عنوان یک کاراکتر، حداکثر ۲۵۶ کاراکتر دارد. `\n` نشانهٔ LF و `\0` نشانهٔ NUL است؛ در سایر escapeها، خود کاراکتر بعدی منظور است. برای مثال `\q` معتبر است. متن اصلی توکن تغییر نمی‌کند و تبدیل به مقدار اجرایی در این فاز انجام نمی‌شود.

علامت منفی جدا از عدد توکن می‌شود؛ `-12` شامل عملگر `-` و ثابت `12` است. در نتیجه `a-12` نیز درست تحلیل می‌شود. بازهٔ ۶۴بیتی در این مرحله به عدد C++ تبدیل نمی‌شود و سرریز تبدیل عددی رخ نمی‌دهد؛ اعتبار بازه به مرحلهٔ معنایی تعلق دارد.

## طولانی‌ترین تطبیق و اولویت

شناسه تا انتهای حروف، ارقام و زیرخط خوانده می‌شود؛ سپس واژهٔ کامل در فهرست کلمات کلیدی جست‌وجو می‌شود. `return` کلمهٔ کلیدی است ولی `returning` شناسه است. `true` و `false` نیز رزروشده‌اند، با دستهٔ جداگانهٔ BOOLEAN.

توضیح‌ها پیش از عملگر `/` بررسی می‌شوند. عملگرهای دوتایی پیش از عملگرهای تکی بررسی می‌شوند، بنابراین `<=` یک توکن است. در توضیح بلوکی، اولین `*/` پایان توضیح است؛ توضیح بلوکی تودرتو نیست. کوتیشن escapeشده پایان رشته نیست.

## موقعیت و خطا

توکن شامل نوع، لکسم عیناً مطابق ورودی و نام فایل، offset بایتی، خط و ستون یک‌مبناست. فاصله‌ها و توضیح‌ها برای خروجی حفظ می‌شوند ولی به تصمیم‌های Parser وارد نمی‌شوند. CRLF یک پایان خط محسوب می‌شود و CR و LF تنها نیز پایان خط‌اند. تب در ستون منطقی یک واحد حساب می‌شود؛ عرض نمایشی آن در HTML چهار فاصله است.

کاراکتر ناشناخته توکن INVALID تولید می‌کند و تحلیل ادامه می‌یابد. نقل‌قول نامعتبر تا پایان همان خط یا پایان فایل جمع می‌شود؛ توضیح بلوکی باز تا EOF جمع می‌شود. خطاهای طول شناسه و رشته و تعداد کاراکترهای نویسه نیز گزارش می‌شوند. EOF توکنی با لکسم خالی است.
